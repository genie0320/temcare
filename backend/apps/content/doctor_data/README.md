# 원장 콘텐츠 입력 데이터

원본: `OLLA_CARE/TIOM64_symptom-response_v8-3.xlsx` 시트 `26년최종`
작업 계약: `docs/10_content_import.md` · 근거: `docs/06_decisions.md` #38·#39

여기 있는 JSON 한 파일 = 시트 한 행(체질 하나)이다. 사람이 문장을 끊고 관점을 붙인
**결과물**이며, `python manage.py import_doctor_content TEM18` 이 읽어 DB에 넣는다.

## 왜 xlsx를 직접 읽지 않나

문장을 끊고 관점 이름을 붙이고 약점 태그를 고르는 것은 자동화할 수 없는 판단이다.
그 판단을 JSON에 눈에 보이게 남겨야 **원장이 검토할 수 있고 git에서 diff가 읽힌다.**
스크립트가 xlsx를 직접 파싱하면 판단이 코드 안에 숨는다.

## 지켜야 할 것

- `description`은 **원장 문장 그대로**다. 요약·재작성 금지(계약서 §4-5).
  손대는 것은 ① 영양소 이름인 주어를 떼는 것(`비타민 B-complex는 …` → `…`)
  ② 붙어 있는 띄어쓰기(`도움이될` → `도움이 될`) 두 가지뿐이다.
  뜻이 흔들리는 비문은 **고치지 않고** `notes.원장확인필요`에 적어 둔다.
- `weakness_ids`가 빈 카드는 서버가 400으로 막는다. 태그가 없으면 고객 화면에
  영원히 안 나온다(계약서 §7).
- 카드의 약점 태그는 **그 문장이 실제로 답하는 약점 중, 이 체질이 가진 것**만
  적는다. 이 체질을 위해 쓰인 문장을 다른 체질이 태그로 끌어가면 #39가 무너진다.
