# 공통 화면 규격 (관리자)

> 프로토타입에서 규격화되어 전 화면에 적용된 규칙. 새 관리자 화면은 이 틀을 그대로 따른다.
> 명세서 UI요소 시트의 `공통-A` / `공통-B` 행과 같은 내용이다.

## A. 목록 화면

```
┌──────────────────────────────────────────────────────┐
│ 화면 타이틀                              [+ 등록]  ← 우측 파랑 1개만
│ 화면 설명 한 줄                                       │
├──────────────────────────────────────────────────────┤
│ [검색            ] [필터▾] [필터▾]                    │
├──────────────────────────────────────────────────────┤
│ No. │ 항목명 │ 연결약점 │ … │ 상태                   │  ← 행 전체 클릭 → 상세
│  12 │ …                                              │
├──────────────────────────────────────────────────────┤
│                     [15▾]  ‹ 1 2 3 ›                 │
└──────────────────────────────────────────────────────┘
```

**규칙**

1. **검색**은 항목명·ID 일부·관점(자유텍스트)을 한 입력창에서 통합 검색한다.
2. **필터**는 두 종류를 혼용한다. 단수 = 일반 드롭다운, 복수 = 체크박스 드롭다운. 화면당 여러 개 배치하며 **폭은 `--filter-w`(176px)로 통일**한다.
3. **맨 앞은 No. 열**이고 내림차순 고정이다(최신이 위).
3-1. **No.·상태처럼 모든 목록에 공통으로 나오는 열은 폭을 고정한다** — No.는 `DataTable`이 `.col-no`(52px)로 이미 고정해 준다. 상태는 `<Column width="80px">`(카드수·유형처럼 짧고 형식이 일정한 열도 같은 방식으로 고정 가능). 나머지(이름·태그처럼 내용 길이가 들쭉날쭉한 열)는 폭을 지정하지 않는다 — 화면마다 상태 열 위치가 오락가락하면 눈이 매번 다시 찾아야 한다.
4. **행 전체가 클릭 영역**이며 상세로 이동한다. 목록에는 편집·삭제 버튼을 두지 않는다.
5. **쪽당 개수**는 15/30/50/100 선택, 페이징은 하단.
6. **주요 액션은 우측 상단 파랑 버튼 하나**. 여러 개 두지 않는다.

## B. 상세 화면

```
┌──────────────────────────────────────────────────────┐
│ ← 목록   화면 타이틀            ← '←목록'은 타이틀 왼쪽 │
├────────────────────────────────┬─────────────────────┤
│ [기본정보 카드]                 │ [게시 박스]          │
│  항목명 …                      │  상태 ▾              │
│                                │  [저장] [삭제]       │
│ [반복 카드 리스트]              ├─────────────────────┤
│  ┌ 카드 1  [삭제] ┐            │ [정보]               │
│  └───────────────┘            │  생성 2026-07-30     │
│  ┌ 카드 2  [삭제] ┐            │  최종수정 …          │
│  └───────────────┘            │  수정자 원장          │
│  [+ 추가]                      │  ID  nut_001         │
│                                ├─────────────────────┤
│ [미디어]                        │ [사용처]             │
│                                │  요법 3건 …          │
│                                ├─────────────────────┤
│                                │ [도움말]             │
└────────────────────────────────┴─────────────────────┘
        3/4 폭                          1/4 폭
```

**규칙**

1. **좌 3/4 본문 + 우 1/4 사이드패널.** 본문은 카드 단위로 섹션을 나눈다.
2. **`← 목록`은 타이틀 왼쪽**에 둔다(우측 아님).
3. **게시 박스**에 상태 + 저장 + 삭제. **취소 버튼은 두지 않는다.**
4. **항목 ID는 우측 '정보' 블록에만 노출**한다. 목록이나 본문에 노출하지 않는다.
5. **정보 블록에 생성일시 · 최종수정 · 수정자**를 항상 표시한다(`created_at` / `updated_at` / `updated_by`). 이 세 컬럼은 모든 마스터 테이블에 있다.
6. **사용처(역참조)** 블록은 연결 관계가 있는 화면에만. 이 항목을 참조 중인 다른 콘텐츠를 보여준다.
7. **편집·삭제는 상세에서만** 가능하다.

## C. 반복 카드 리스트 (B-2 패턴)

영양소·약재처럼 "마스터 1건 + 하위 카드 N건" 구조에 쓴다.

- 카드 = (항목 × 관점) 단위이며 **약점은 카드에 n:m으로 붙는다.** 약점당 카드 1개가 아니다.
- 관점(영양소) / 효능기전(약재)은 **마스터 없는 자유 텍스트 + 기존값 자동완성**. 공백 제거로 정규화한다.
- 각 카드에 삭제 버튼, 리스트 하단에 점선 테두리 `+ 추가` 버튼.

## D. 실피커 모달

요법관리에서 식품군·혈자리·제품을 연결할 때 쓴다.

- 모달 안에서 검색·필터 후 다중 선택.
- **식품군 피커는 요법관리와 64체질에서 동일한 컴포넌트**를 쓴다(64체질에만 약점 필터가 추가로 붙는다).
- 극성이 있는 항목(식품군)은 권장/제한 배지를 함께 노출한다.

## E. 큐레이션 (후보 → 선택)

64체질 상세에서만 쓴다. 좌측 후보(약점 태그로 자동 필터) → 우측 선택. 드래그로 순서 조정.

**선택 단위 주의**: 영양·약재는 **카드 id**(nutrient_card / herb_card), 식품군은 food id다.

## F. 상태 값

전 마스터 공통: `게시` / `초안` / `숨김`. 검수 흐름을 쓰는 화면은 `검수요청`이 추가된다.

## G. 빈 상태 · 검증

- 약점 태그가 없는 콘텐츠는 고객 화면에 나타나지 않는다 → **약점 선택을 저장 시 필수 검증**한다.
- 빈 섹션은 고객 화면에서 자동으로 숨긴다.
- 예측질환 %는 **합계 100% 검증을 하지 않는다**(질환별 독립 발병율).
- IDEA끼리 조합되는 예외(TEM54)가 있으므로 **약점 개수 검증을 하지 않는다.**
