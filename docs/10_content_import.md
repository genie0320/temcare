# 원장 콘텐츠 입력 작업 계약

> 원본: `OLLA_CARE/TIOM64_symptom-response_v8-3.xlsx` 시트 **`26년최종`** (64행 = TEM01~TEM64)
> 근거 결정: `docs/06_decisions.md` **#38**(원본 해석) · **#39**(입력 방식)
> 이 문서는 **무엇을 어디에 넣을지의 계약**이다. 여기서 벗어나야 할 이유를 찾으면 진행하지 말고 먼저 물어볼 것.

## 1. 한 줄 요약

원장이 쓴 **긴 문장 덩어리**를 문장 단위로 끊어 **마스터에 관점 카드로 넣고**, 각 체질 화면에서 **골라 조립**한다.

## 2. 방식 (영양요법 기준 — 다른 열도 같은 구조)

```
① 문장으로 끊는다     한 유형의 '영양요법' 셀(평균 695자) → 영양소별 문장으로 분해
② 중복을 접는다       64유형에 흩어진 같은 뜻의 문장을 하나로 모은다
③ 마스터에 넣는다     (영양소 × 관점) = nutrient_card 한 장
④ 체질에서 조립한다   그 체질이 보여줄 카드를 고른다
```

| 단계 | 테이블 | 관리자 화면 |
|---|---|---|
| ③ 항목 | `nutrient` (name, image) | **adm_022 영양소 마스터** |
| ③ 관점 카드 | `nutrient_card` (nutrient, **perspective**, description, weaknesses) | 같은 화면의 카드 영역 |
| ④ 조립 | `tem_type_curation` (kind='nutrient', ref_id, sort) | **adm_002 64유형 상세 = '체질관리'** |

**왜 이렇게 하나** — 같은 마그네슘인데 유형마다 설명이 다르다. 그건 오류가 아니라 원장의 의도다.

| 유형 | 관점 | 문장 |
|---|---|---|
| TEM03 (변비) | 장연동 | 평활근 이완과 삼투 작용으로 장내 수분 증가, 연동운동 리듬 정상화 |
| TEM06 (소화불량+변비) | 장연동+위장 | …변비에 도움, 위장관 긴장 완화로 소화불량에도 간접적으로 |
| TEM18 (추위+소화불량+변비) | 순환·자율신경 | 혈관이완으로 순환개선, GABA 활성화로 자율신경 균형 회복 |

→ **마그네슘 카드 3장**(관점이 다름). 각 체질이 자기 것을 고른다.

## 3. 열 ↔ 모델 대응

| 시트 열 | 모델 | 조립(큐레이션) |
|---|---|---|
| No | `tem_type.id` | — |
| 템 유형 이름 | `tem_type.name` | — |
| TEM 약점 | `tem_type.weaknesses` (`+` 분리) | — |
| 별명 | `tem_type.nickname` | — |
| 체형 | `tem_type.body_desc` | — |
| 건강적신호 | `health_sign` (`☑` 분리) + 약점 태그 | ✗ 약점 태그로만 자동 |
| 예측질환 | `illness` + `tem_type_illness.pct` | 체질별 % 직접 입력 |
| 영양요법 | `nutrient` + `nutrient_card(perspective)` | ✅ `kind='nutrient'` |
| 식이요법 | `food` (polarity 권장/제한) | ✅ `kind='food'` |
| 생활요법 | `article` | ✗ **큐레이션 대상 아님** — 약점 태그로만(#3) |
| 지압 혈자리/마사지 | `acupoint` | ✗ 약점 태그로만 |
| 인생처방 | `herb` + `herb_card(mechanism)` | ✅ `kind='herb'` |

## 4. 하지 말 것 (확정)

1. **`TEM 건강법` 열을 넣지 않는다.** 평균 9,790자로 분량의 절반 이상이지만, '가뿐차 / 습관 / 제품추천'으로 쪼개 **템라이프**에 실을 계획이고 템라이프는 2차 이연이다(#11·#38).
2. **`(원장에게만 제시) 후보처방` 열을 고객 API에 넣지 않는다.** 원장 전용이고 내용도 방제(고방)다 — 인생처방은 방제가 아니라 **약재**다(CLAUDE.md §6).
3. **`인생처방` 열은 64행 중 1행만 채워져 있다.** 없는 것을 지어내지 않는다. 빈 채로 둔다(#38).
4. `생애주기별 건강` · `D 기본/운동/식단/음악/아트/바이오리듬` 열은 원본이 비어 있다. 1차 보류 항목과 일치한다.
5. **원장의 문장을 요약하거나 재작성하지 않는다.** 자르고 다듬는 것(어미 정리·중복 제거)까지다. 의학적 표현을 임의로 바꾸면 안 된다.

## 5. ★ 시드 id 어긋남 — 먼저 처리할 것

`prototype/ollacare.sqlite`가 id를 잘못 붙였다. **id로 그냥 덮어쓰면 두 유형이 뒤섞인다.**

| | 현재 로컬 DB `TEM05` | 시트 `TEM05` | 시트 `TEM18` |
|---|---|---|---|
| 이름 | TE-5 | E 4형 | **TE 5형** |
| 약점 | 추위+소화불량+변비 | 부종 | **추위+소화불량+변비** |
| 별명 | 매일 겨울을 사는 | 물 먹은 스펀지 | **매일 겨울을 사는…** |

→ 현재 `TEM05`의 내용은 **시트 기준 `TEM18`**이다. 실데이터 입력 전에 정리한다.

## 6. 진행 순서

1. **`TEM18`(TE 5형) 한 유형의 `영양요법` 열만** 끝까지 넣어본다 — 마스터 카드 생성 → 약점 태그 → 체질관리에서 조립.
2. 관리자 화면(`make dev`)에서 실제로 보이는지 확인하고, 고객 처방 화면(`make dev-app`)까지 한 바퀴 돈다.
3. **여기서 멈추고 사용자에게 보여준다.** 이 한 벌이 나머지의 본보기가 된다 — 여기서 어긋나면 64배로 어긋난다.
4. 승인 후 나머지 열 → 나머지 유형.

## 7. 지켜야 할 것 (프로젝트 공통)

- **감사로그 우회 4종 금지** — `QuerySet.update()` / `.delete()` / `bulk_create` / `bulk_update` / 원시 SQL. 대량 입력이라 특히 유혹이 크다. 반드시 인스턴스 `save()` / `create()`로. (`bash backend/scripts/check_audit_bypass.sh`로 확인)
- **약점 태그 없는 콘텐츠는 저장되지 않는다**(서버가 400으로 막는다). 태그가 없으면 고객 화면에 영원히 안 나온다.
- **약점 '개수'는 검증하지 않는다** — IDEA끼리 조합되는 예외(TEM54)가 있다.
- 커밋 전 `make test`(백엔드 pytest + 프론트 vitest) · `make lint`.
- **커밋만 하고 끝내지 말 것 — 푸시까지 해야 CI가 봐준다.** 실제로 푸시 안 된 커밋 때문에 CI가 한 번 무력화된 적이 있다.
- 커밋은 사용자가 요청할 때만.
